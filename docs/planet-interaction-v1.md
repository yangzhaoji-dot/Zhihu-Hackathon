# 星球之间交互 v1

## 目标

星球之间的互动不是为了“像游戏”，而是为了让用户更容易看见**观点之间的关系与变化**。

一颗星球代表一个观点。星球之间的每一种物理动作，都必须对应一种明确的认知动作；如果一个动画不会改变用户对观点关系的理解，也不会改变认知图，就不应成为核心交互。

> **物理隐喻负责让关系可感知，AI 负责让关系可解释，用户负责决定关系是否进入宇宙。**

---

## 统一交互语言

### 1. 引力感应 Gravity

**动作：** 用户拖动一颗观点星球靠近另一颗。

**作用：** 让用户意识到“这两个观点可能值得放在一起看”。

**系统行为：**
- 被拖动星球跟随指针移动，但松手后恢复原本布局；
- 进入引力范围时，目标星球出现光场反馈；
- 不调用 AI，不修改图，不产生新观点；
- 如果两颗星球已经有关系，地图保留已有关系桥作为上下文。

Gravity 是低成本预览，不代表系统已经判断两者有关。

### 2. 观点碰撞 Collision

**动作：** 两颗星球真正接触并松手；或通过列表按钮选择两颗星球。

**作用：** 回答“这两个观点真正在哪些地方一致、冲突或互补？”

**AI 输出：**
- 共识；
- 核心分歧；
- A / B 各自成立条件；
- 证据比较；
- 尚未覆盖的信息；
- 一个可能的综合观点。

Collision 本身只分析，不修改认知宇宙。

### 3. 建桥 Bridge

**动作：** Collision 后，用户认为两个观点都应该继续独立存在，于是选择建立关系。

**作用：** 把“两个观点之间是什么关系”写入认知图，而不是强行合并它们。

用户可以选择：
- `add`：补充；
- `cond`：条件；
- `oppose`：对立；
- `support`：支持；
- `refute`：反驳。

**图变化：**
- 不新增观点节点；
- 两颗星球都保留；
- 写入一条 semantic relation；
- 如果同一对星球之前已有关系，新判断替换旧关系，避免冲突边无限堆积；
- 关系会在星群中以“认知桥”呈现，在观点聚焦卡中也可以查看。

### 4. 融合 Fusion

**动作：** Collision 后，用户认为两个观点能够产生一个真正独立的新判断。

**作用：** 形成第三颗星球。

**约束：**
- 只有真实 AI Collision 结果允许 Fusion；fallback 不会物化新观点；
- 新星球保存两个 parent；
- 继承两边可追溯的来源集合；
- 原来的两颗星球不消失；
- Fusion 是观点演化，而不是用“平均立场”消除分歧。

---

## 为什么同时需要 Bridge 和 Fusion

很多观点之间有重要关系，但并不应该被合成一句话。

例如：

> A：长期损害身心的工作，离开可以是一种止损。
>
> B：没有现金流时裸辞，可能只是把职业焦虑换成生存焦虑。

它们可以被理解为互相限定条件，因此适合 **Bridge / Condition**；如果进一步形成“退出决策应该同时比较持续损耗与退出成本”这一独立判断，则可以 **Fusion** 出第三颗星球。

因此：

> **Bridge 表达关系，Fusion 表达新思想。**

## 与星球内部交互的关系

当前产品有两个互补的认知循环：

### 星球内部

`阅读来源 → 划选片段 → 形成观点 → AI 评价 → Merge / Fork`

解决：**一个观点如何被理解、修正和继续生长。**

### 星球之间

`Gravity → Collision → Bridge / Fusion`

解决：**多个观点如何产生关系与新的结构。**

二者共同组成完整闭环：

> 人类留下观点 → 用户进入观点形成自己的理解 → 新观点回到星系 → 与其他观点发生关系 → 宇宙继续生长。

## 下一阶段候选：携带碎片 Carry Fragment

这项能力暂不作为 v1 阻塞项，但它是连接“内部”和“之间”的下一步重点。

设想：
- 用户在星球 A 中收藏了一段原文；
- 返回星群后，可以把这段认知碎片带到星球 B；
- 进入 B 时，这段材料作为一个明确的外来材料参与新的观点形成；
- 系统记录它来自哪颗星球、哪份来源，而不是把两边来源混为一谈。

它表达的不是“观点 A 和 B 合并”，而是：

> **一段在 A 中看到的材料，改变了我理解 B 的方式。**

这是未来最值得继续做深的跨星球交互。

## 交互与可信度原则

- 拖动、靠近和视觉反馈不应偷偷调用昂贵 AI；只有 Collision 才进入深分析。
- AI 分析结果先展示，任何 Bridge / Fusion 都需要用户确认。
- 关系类型由用户最终决定；AI 可以解释，不替用户强制写图。
- 不把热度、赞同数当作观点正确性的权重。
- Demo 关系和材料仍必须明确标记为演示内容。
- 手机 / 键盘用户始终可以通过列表按钮完成与拖动等价的核心操作。
- 不暴露或依赖模型私有 Chain-of-Thought。

## 当前实现状态

`cognitive-orbit-v1` 已实现：

- Cluster 内直接拖动观点星球；
- 引力范围与碰撞范围反馈；
- 接触松手后自动打开 Collision 并触发分析；
- 按钮式选择作为 fallback；
- Bridge：五类语义关系写入当前 session graph；
- 持久关系桥视觉层；
- Planet Focus 展示与其他观点的具体关系；
- Fusion：产生第三颗星球；
- Reset 恢复 Demo 初始宇宙；
- 单元测试覆盖 Bridge graph mutation；
- 浏览器验收覆盖 Gravity / Collision / Bridge / Fusion。

当前 B 模块公共入口为 `src/components/planet-interaction/index.ts`。星球视觉、拖拽/引力判定、Collision 面板和 relation overlay 均从这里导出；Galaxy 舞台只组合这些能力，并通过 `InteractionState` 向 Universe 层提供语义状态。
