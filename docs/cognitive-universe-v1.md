# 知乎宇宙 / Cognitive Universe v1

> **把知乎里的问题、观点与真实讨论，组织成一个可以探索、理解、重组和继续生长的认知宇宙。**

本文档冻结当前黑客松版本的产品逻辑、交互原则、AI 角色、视觉语言与数据边界。后续实现应优先遵守这里的产品抽象，而不是回到早期的 3D 游戏 / NPC / 自由移动路线。

---

## 1. 产品定位

知乎里有大量真实的人类经验、判断、争论和案例，但这些内容通常以长回答、评论和时间线形式分散存在。

用户面对一个复杂问题时，真正困难的并不是“没有答案”，而是：

- 不知道这个问题到底有哪些不同的思考方向；
- 不知道一个观点为什么会成立；
- 不知道不同观点真正冲突在哪里；
- 阅读很多回答后，也很难形成自己的结构化判断。

**知乎宇宙**不是要替代知乎回答，也不是把回答简单总结成若干 bullet points。

它要做的是：

> **让用户先看见“人们如何思考”，再进入一个观点，阅读它背后的真实材料，最后基于自己真正读过和选择过的内容形成新的观点。**

因此我们把产品分成三个认知层级：

1. **星系层：发现观点**
2. **星球内部：形成 / 修正观点**
3. **星球之间：碰撞 / 融合观点**

---

## 2. 世界观

世界观不是单纯的包装，它服务于整个信息架构。

### 开场叙事

> 很久以前，人工智能革命爆发。  
> 数字世界与现实世界逐渐失去边界。  
> 后来，地球消失了。  
> 但人类的思想没有消失。  
> 问题、观点、争论与记忆，最终坍缩成了一片高维认知宇宙。

在这片宇宙里：

- **一个问题形成一片星系；**
- **一个观点成为一颗星球；**
- **真实回答、案例与片段构成星球内部的认知材料；**
- **用户是重新进入这片宇宙的“寻知者”。**

这套隐喻对应真实产品结构：

- 问题 = Question Galaxy
- 思考方向 = Cognitive Cluster
- 观点 = Opinion Planet
- 原始回答 / 摘录 = Cognitive Material
- 新观点 = Evolved Planet
- 观点关系 = Orbit / Relation

---

## 3. 核心产品主循环

完整主流程：

**世界观开场**  
→ **首页搜索 / 推荐问题**  
→ **问题星系**  
→ **选择思考方向**  
→ **进入观点星群**  
→ **聚焦具体观点星球**  
→ **登陆星球**  
→ **阅读真实来源文本**  
→ **自己划选重要片段**  
→ **AI 根据选中文本形成新观点**  
→ **独立 AI 评价**  
→ **用户决定 Merge / Fork**  
→ **回到星系看到变化**  
→ **继续进行星球碰撞 / 融合**

一句话概括：

> **发现观点 → 进入观点 → 选择材料 → 形成观点 → 让观点继续生长。**

---

# 4. 第一层：星系 —— 发现观点

## 4.1 问题星系

一个问题不是一篇文章，而是一片完整的认知空间。

例如：

> 年轻人到底该不该裸辞？

进入以后，用户首先看到的是：

- 中央巨大的问题核心；
- 大量观点星球；
- 观点自然形成若干思考方向；
- 从远处先看到“结构”，而不是密密麻麻的文字。

### 关键目标

用户第一眼应该产生三个感受：

1. **这个问题下面有很多不同的观点。**
2. **这些观点不是随机的，它们存在结构。**
3. **我可以选择一个思考方向深入。**

## 4.2 Cluster 不是立场阵营

不能简单分成“支持 / 反对”。

Cluster 表示不同的**思考维度 / 关注角度**，例如：

- 身心与边界
- 经济与资源
- 职业成长
- 个人价值
- 行业与环境
- 推理与证据

一个 cluster 内部可以存在互相矛盾的观点。

这比二元站队更符合“高维认知空间”的产品概念。

## 4.3 Semantic Zoom

产品的核心导航不是页面跳转，而是**语义缩放**：

- 远处：看问题整体结构；
- 靠近 cluster：看到具体思考方向；
- 继续靠近：看到具体观点；
- 聚焦观点：准备登陆星球。

因此：

> **缩放 = 导航，尺度变化 = 信息层级变化。**

# 5. 第二层：星球内部 —— 形成 / 修正观点

这里是当前版本最重要的 AI-native 交互。

## 5.1 星球本身已经有一个观点

进入一颗星球时，用户知道它原本代表什么观点。

例如：

> **长期消耗身心的工作，离开也可以是一种止损。**

我们的目标不是让用户“还原标准答案”，而是：

> **围绕一个已有观点，阅读与它相关的真实材料，并在阅读过程中形成一个可能不同的新观点。**

## 5.2 用户只面对原始文本

不让 AI 先替用户把内容拆成“证据 / 条件 / 反例”。

用户看到的基本单位是：

> **知乎回答里的原始文本片段。**

用户自己阅读，然后直接划选认为真正影响自己判断的一句或一段。

交互非常简单：

> **读 → 划 → 收下**

被选中的片段进入用户自己的“认知片段”集合。

### 为什么这样做

因为“用户留下哪些句子”本身就是一种思考。

用户不是替模型挑训练数据，而是在表达：

> **这些内容进入了我的判断过程。**

## 5.3 形成我的观点

当用户收集至少若干段材料后，可以点击：

> **形成我的观点**

第一阶段 AI：

- 只能看到用户真正选中的文本；
- 看不到原星球观点；
- 看不到赞同数等热度信息；
- 不允许补充材料之外的具体事实。

这样可以避免：

- 直接照抄原观点；
- 被高赞信息偷偷引导；
- 生成无法追溯的事实。

AI 的任务不是替用户决定“正确答案”，而是：

> **把用户实际阅读后留下来的认知材料，凝结成一句清晰、可讨论的观点。**

## 5.4 第二阶段：独立评价

观点生成完成后，再进行一次独立 AI 评价。

此时 evaluator 可以看到：

- 原星球观点；
- 用户新观点；
- 用户真正选择的文本。

评价维度：

- **Grounding**：新观点是否真的被材料支持；
- **Coherence**：内部是否自洽；
- **Specificity**：是否具体，而不是“具体情况具体分析”；
- **Boundary**：是否意识到适用条件与边界；
- **Novelty**：相比原观点增加了什么；
- **Overall**：综合质量。

分数是**反馈**，不是游戏目标。

我们不鼓励用户为了刷 100 分而堆材料。

## 5.5 AI 判断新观点与原观点的关系

关系类型：

- `refinement`：补充条件 / 边界
- `extension`：从原观点继续延伸
- `revision`：保留部分核心但修改关键判断
- `counterpoint`：形成明显不同判断
- `new_dimension`：引入原观点没有考虑的新变量

随后 AI 给出一个建议：

- **Merge**：更适合并入原星球；
- **Fork**：更适合形成新的独立星球。

但 AI 只有建议权。

> **最终决定由用户完成。**

---

# 6. Merge 与 Fork

## 6.1 Merge —— 原星球发生进化

如果用户形成的新观点只是补充原观点的条件或边界：

> 不制造一颗几乎重复的新星球。

而是直接更新原星球：

- 保留原 id 和空间位置；
- 更新观点表达；
- 保存原始观点；
- 保存新增加的条件；
- 保存用户选中的来源材料。

概念上：

> **同一颗思想变得更完整了。**

## 6.2 Fork —— 产生一颗新星球

如果新观点已经拥有独立判断：

> 从原星球分叉出一颗新的观点星球。

新星球保留：

- 父观点；
- 用户选中的来源；
- 用户摘录；
- AI 评估关系；
- 生成时间。

返回星系后立即可见，并可以再次登陆继续探索。

这意味着：

> **认知宇宙不是静态数据库，而会因为后来的人继续思考而生长。**

# 7. 第三层：星球之间 —— 碰撞 / 融合观点

星球内部解决：

> 一个观点怎样被理解和继续演化？

星球之间解决：

> 两个观点真正是什么关系？

## 7.1 观点碰撞

用户可以从同一个星群中选择两颗观点。

AI 分析：

- 两者的共识；
- 真正的核心分歧；
- A 成立的条件；
- B 成立的条件；
- 证据结构差异；
- 当前讨论仍缺失的信息；
- 是否存在一个有价值的综合观点。

重要原则：

> **不是简单判断“谁对谁错”。**

很多表面冲突，本质上只是：

- 优化目标不同；
- 前提不同；
- 时间尺度不同；
- 价值排序不同。

AI 的价值在于把这些隐含结构显式化。

## 7.2 Fusion —— 形成第三颗星球

碰撞分析完成以后，用户可以确认：

> **融合成新星球**

融合不是自动发生。

必须先让用户看到分析，再由用户确认。

融合星球保留：

- 两个 parent；
- 双方来源集合；
- AI 综合观点；
- 与父观点的关系。

# 8. AI 在产品里的角色

AI 不应该只是右下角的聊天机器人。

它是整个认知宇宙背后的**隐形导演**。

AI 主要承担四件事：

1. **结构化空间**  
   把大量回答组织成问题星系、思考方向与观点节点。

2. **观点凝结**  
   把用户真正读过、真正选择的材料组织成一句新的观点。

3. **认知评价**  
   检查观点是否有材料支撑、是否具体、是否有边界。

4. **观点关系推演**  
   分析两个观点的共识、冲突、条件和可能的综合方向。

核心原则：

> **AI 不替代知乎的人类内容，而是重新组织人类内容。**

知乎提供真实经验与思考材料；AI 负责把它们变成一个可以探索和继续思考的认知空间。

# 9. 数据与可信度原则

这是产品必须严格遵守的底线。

## 9.1 原文优先

星球内部给用户阅读的是来源文本，而不是 AI 改写后的“伪原文”。

## 9.2 用户选择必须可验证

用户提交给模型的每一个 excerpt 必须是允许来源文本的真实子串。

服务端负责验证。

## 9.3 Demo 与真实数据严格分离

当前仓库包含用于演示交互的 authored demo 数据。

它必须明确标注为：

> **演示材料**

不能冒充：

- 真实知乎作者；
- 真实回答；
- 真实赞同数；
- 真实统计。

真实检索模式才展示可追溯的知乎来源和链接。

## 9.4 不伪造 AI 成果

AI 不可用时：

- 保留用户已选择材料；
- 明确显示不可用；
- 不用 fallback 假装生成一个“AI 新观点”。

## 9.5 不暴露模型私有 Chain-of-Thought

当前版本只使用普通模型 API。

我们控制的是：

> **输入材料 + 显式输出结构**

而不是假装拿到了模型内部真实思维链。

# 10. 视觉设计原则

总体视觉目标：

> **深邃但不昏暗，空旷但不空洞，科幻但不赛博，丰富但不杂乱。**

## 10.1 不是物理宇宙模拟器

宇宙是“认知”的隐喻。

不追求：

- 写实太阳系；
- NASA 模拟；
- 真实天体物理；
- 游戏化宇宙驾驶。

## 10.2 2D / 2.5D Web-native

整体使用：

- SVG / CSS / Canvas；
- Semantic Zoom；
- 大尺度光场；
- 星云；
- 前中后景；
- 光晕、模糊、视差；
- 克制的粒子系统。

保持网页原生交互：

- 点击；
- Hover；
- 拖动；
- 滚动；
- 文本选择。

不做自由移动角色和复杂游戏控制。

## 10.3 动画必须表达认知动作

动画不是装饰。

- Zoom Out = 看全貌
- Zoom In = 深入思考方向
- 星群形成 = 发现结构
- 星球聚焦 = 进入具体观点
- Merge = 观点被修正
- Fork = 新观点产生
- Collision = 两个思想发生关系

## 10.4 粒子分层

粒子不是越多越好。

- Opening：承担叙事
- Ambient：让宇宙保持生命感
- Cluster Atmosphere：表达区域气候
- Interaction：回应 hover / focus / zoom
- Narrative Event：只在坍缩、生成、融合等强事件里提升强度

# 12. 当前刻意不做的事情

以下内容属于下一阶段，而不是当前 hackathon 主闭环的 blocker：

- 云端持久化个人宇宙；
- 多用户共同演化；

- 自由移动 2.5D 游戏；
- 大规模实时协同宇宙。

# 13. 产品最终表达

我们不想做：

> “把知乎回答画成一堆星球。”

我们真正想做的是：

> **让一个问题变成可以探索的认知空间。**

再进一步：

> **知乎留下人类真实的思考素材；用户选择自己真正读进去的内容；AI 帮助这些材料凝结成新的观点；新的观点重新回到宇宙里，继续与其他思想发生关系。**

因此，这个宇宙不是静态的。

> **它会随着人继续思考而生长。**
