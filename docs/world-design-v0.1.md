# OpinionSpace 世界与引导角色设计 v0.1

> 状态：产品与视觉设计提案，尚未实现。本文用于记录当前方向，不代表最终美术、交互或赛事授权已经确认。

## 1. 核心方向

保留现有的 3D 观点宇宙与火箭旅行，将其作为议题选择和世界切换的统一入口。用户发射火箭后，降落到一个可探索的斜俯视二维世界；不同议题可以进入不同视觉风格的世界。

世界不是随机换皮，而是对议题分歧结构的可视化表达：

- 问题决定星球；
- 核心分歧决定世界类型和空间结构；
- 观点群决定区域；
- 单个有来源的观点由 NPC 承载；
- 证据状态决定道路、迷雾、桥梁和建筑状态；
- 用户形成的判断改变世界最终状态。

## 2. 用户旅程

| 阶段 | 场景 | 用户行为 | 系统作用 |
| --- | --- | --- | --- |
| 1 | 观点宇宙 | 搜索或选择知乎议题 | 分析议题类型和主要分歧 |
| 2 | 星球轨道 | 查看星球名称与简介 | 推荐对应的世界类型 |
| 3 | 火箭发射 | 决定进入议题 | 加载来源、观点和世界配置 |
| 4 | 星球降落 | 进入二维世界 | 加载地图、NPC 与初始环境状态 |
| 5 | 世界探索 | 与 NPC 交流、寻找线索 | 展示观点、条件和原文依据 |
| 6 | 观点比较 | 选择两个观点进行比较 | 输出共识、分歧、条件和证据缺口 |
| 7 | 形成判断 | 保存自己的当前看法 | 生成个人判断记录或“认知坐标” |
| 8 | 返回宇宙 | 乘火箭离开 | 保存探索状态并更新星球轨道 |

火箭旅行不只是装饰，它还承担加载过渡和认知预告。飞行途中可展示本次纳入的材料范围、主要分歧类型、世界名称以及尚未确认的信息。

## 3. 世界类型

| 世界 | 适用议题 | 核心隐喻 | 美术方向 | 代表地点 | MVP 范围 |
| --- | --- | --- | --- | --- | --- |
| 分岔之城 | 升学、就业、职业与人生选择 | 不同答案通向不同目标 | 低饱和写实像素城市 | 分岔车站、机会市场、训练工坊、条件桥 | 完整制作 |
| 失落档案馆 | 新闻、历史、科学与事实核查 | 真相散落在不完整记录中 | 旧纸张、胶片与档案拼贴 | 原始记录室、引用长廊、缺页区、矛盾证词室 | 小型版本 |
| 无罪剧场 | 道德、责任与公共事件 | 每个人都在自己的位置上陈述 | 黑色舞台、版画与聚光灯 | 证词席、责任天平、幕后走廊、空陪审席 | 入口预览 |
| 回声森林 | 亲密关系、家庭、自我认同 | 人听见的也可能是自己的回声 | 超现实森林、雾气与水彩像素 | 回声湖、边界树林、未寄出的信屋、记忆树 | 后续版本 |
| 永动机械城 | AI、自动化、效率与科技发展 | 每种进步都需要某种燃料 | 工业科幻、金属与冷色灯光 | 效率工厂、代价控制室、失控协议区、人工花园 | 入口预览 |

世界类型由议题的主要分歧机制决定，而不是由关键词或情绪随机决定。如果一个议题同时包含事实、价值和现实选择，可以通过世界中的入口进入另一个世界，但 MVP 不承诺完整的多世界串联。

## 4. 世界内部的信息映射

| 产品信息 | 场景表达 |
| --- | --- |
| 议题 | 一颗星球 |
| 核心分歧 | 世界地貌与道路结构 |
| 观点群 | 城区、建筑群或自然区域 |
| 单个观点 | NPC |
| 观点成立条件 | 门票、钥匙、桥梁或通行条件 |
| 原文依据 | NPC 携带的书、档案、录音或物品 |
| 观点关系 | 道路、桥梁、裂缝和隧道 |
| 共同前提 | 两个区域共享的地标 |
| 证据不足 | 迷雾、停工建筑或断裂道路 |
| AI 推演观点 | 明确标注的半透明或未完成 NPC |
| 用户判断 | 用户建立的观测站或认知坐标 |

场景变化必须对应认知变化。例如发现共同前提时出现桥梁，确认双方关注目标不同时出现两条不同终点的道路，发现证据不足时保留迷雾而不是强行融合观点。

## 5. 引导角色：刘看山的跨世界化身

设想由知乎品牌角色刘看山担任跨世界引导者。世界风格不断变化，但引导者保持同一身份，并根据世界更换服装、职业和手持物。

| 场景 | 化身 | 服装与物品 | 引导职责 |
| --- | --- | --- | --- |
| 观点宇宙 | 星球导航员 | 航天服、星图与通信器 | 帮助用户选择议题星球 |
| 火箭内部 | 飞船驾驶员 | 驾驶服与分析屏幕 | 解释本次探索目标和材料范围 |
| 分岔之城 | 车站管理员 | 制服、帽子、路线图与怀表 | 提醒不同答案可能服务于不同目标 |
| 失落档案馆 | 档案管理员 | 长外套、眼镜、文件夹与印章 | 帮助用户寻找来源和证据 |
| 无罪剧场 | 剧场书记员 | 正装、胸针、记录本与天平 | 区分事实、责任和价值判断 |
| 回声森林 | 提灯人 | 斗篷、围巾、提灯与信件 | 引导用户理解经历、条件和情绪 |
| 永动机械城 | 维修工程师 | 工装、防护镜、扳手与机械核心 | 揭示效率背后的条件和代价 |

跨世界应保留稳定的角色轮廓、主要识别色、星图徽章、对话头像构图和基础动作，只改变服装、手持物、局部材质和世界专属动画。刘看山可以保持亲和感，世界背景则采用更成熟、克制、低饱和的视觉语言，避免整套产品变成幼态卡通风格。

### IP 使用边界

刘看山属于知乎品牌 IP。公开资料中存在职业换装和联名形象的先例，但这不等于本项目已自动获得改编和再分发授权。正式制作前需要向赛事方确认：

1. 是否提供参赛专用的刘看山素材包；
2. 是否允许制作像素化、换装等衍生形象；
3. 是否允许将相关素材随公开 GitHub 仓库发布；
4. 提交页、演示视频和线上 Demo 是否有额外品牌使用要求。

在获得确认前，代码和公开资产应使用非品牌化的“白色狐狸导航员”占位，不提交自行生成的刘看山衍生素材。

参考：知乎历史 IP 合作资料中展示过旅行者、工程师、建筑师等刘看山职业造型：<https://zhstatic.zhihu.com/toppa/01li/dianshanghangye2021.pdf>

## 6. 美术生产原则

- 各世界可以使用不同的材质、配色和表现技法，但统一使用斜俯视二维视角、相同交互逻辑和稳定的角色比例。
- 优先建立 32×32 或 48×48 的模块化场景规范，避免让生成模型直接输出整张不可交互的地图。
- 生成模型可以用于概念图、区域主题和单体素材参考；最终地图应由可点击、可碰撞、可替换的结构化游戏对象组成。
- 场景名称和中文提示由界面动态渲染，不写死在生成图片中。
- 现成卡通素材只用于灰盒和玩法验证，不作为最终视觉目标。
- 最终素材需记录来源与许可证；第三方素材是否可随公开仓库再分发要单独核对。

## 7. 看山对话与环境叙事

看山不仅发布任务，还要帮助用户理解“为什么世界会变成这样”。场景先引起疑问，看山再将环境现象还原成当前材料中可验证的观点结构。

推荐的对话顺序是：

1. 用户观察到场景异常；
2. 看山说明当前材料中的可验证事实；
3. 看山区分事实、系统解释和未知部分；
4. 用户决定查看来源、继续搜索、标记待调查或前往其他区域。

例如用户走进荒凉区域：

> 用户：为什么这里这么荒凉？
>
> 看山：因为在我们目前找到的 18 条回答里，只有一位答主提到了这类人的处境。
>
> 看山：这不代表这里的观点是错的，只代表它很少出现在当前材料里。
>
> 看山：要看看他留下的原文吗？

### 环境隐喻与对话提示

| 场景现象 | 当前材料中的可能含义 | 看山的解释方向 |
| --- | --- | --- |
| 荒凉地区 | 某类处境很少被讨论 | “这里只有少数人的声音，不代表这里没有人生活。” |
| 拥挤市场 | 大量回答重复相似理由 | “这里看起来很热闹，但很多人其实在重复同一个理由。” |
| 浓雾区域 | 当前证据不足 | “现有材料还不足以判断前面会发生什么。” |
| 断裂桥梁 | 两个观点缺少共同前提 | “他们用了相同的词，却没有在谈同一件事。” |
| 两条反向道路 | 观点追求的目标不同 | “一条路追求更快抵达，另一条路在意能否独自走完。” |
| 停工建筑 | 有结论但论证尚不完整 | “这里有一个结论，但建造它的人没有留下足够依据。” |
| 废弃车站 | 观点依赖的条件可能已经变化 | “这条路线曾经有效，但它依据的环境可能已经改变。” |
| 巨大纪念碑 | 高赞或高频观点 | “被看见最多不等于最可靠。” |
| 地下通道 | 隐藏的共同条件 | “地面上两边互不相让，地下却连接着同一个前提。” |
| 无人房屋 | 讨论中缺失的相关人群 | “大家都在替这里的人说话，但我们还没有找到他们自己的声音。” |

环境隐喻不能被直接当作事实。荒凉只能表达“当前纳入材料中出现较少”，不能自动推断为没人支持、不重要或被忽略的真相。看山的台词应尽量同时给出观察、证据范围和不确定性。

看山的主要对话触发点包括：火箭起飞前、飞行途中、初次降落、用户观察到异常环境、完成一组 NPC 对话、准备比较两个观点、比较结果出现，以及用户准备返回宇宙。对话应短而可跳过，避免用长篇说明替代探索。

## 8. 后期声音设计

音效和配乐放在核心交互完成后制作，但需要提前预留语义明确的触发点。声音不能承担唯一的信息传递渠道，重要状态仍需有视觉和文字反馈。

### 跨世界声音

- 火箭发射、航行和降落；
- 看山出现或准备解释环境；
- 找到可回溯的原文证据；
- 发现观点关系或共同条件；
- 遇到证据不足和道路受阻；
- 保存个人判断并获得认知坐标。

### 世界声音方向

| 世界 | 环境声与音乐方向 |
| --- | --- |
| 观点宇宙 | 空灵合成器与无线电 |
| 分岔之城 | 车站广播、远处车辆与克制钢琴 |
| 失落档案馆 | 纸张、打字机与磁带噪声 |
| 无罪剧场 | 木槌、脚步回声与低音弦乐 |
| 回声森林 | 风声、水滴与遥远人声 |
| 永动机械城 | 齿轮、电流与工业节拍 |

看山可以拥有一段固定的短旋律，在不同世界使用不同乐器和材质重新演绎，以统一风格差异明显的世界。首个版本只需制作关键反馈音效，完整背景音乐可以继续后置。

## 9. 首个验证议题

建议先用“大学生应该尽早使用 AI 学习编程，还是先独立掌握基础？”验证分岔之城：

- 自动工坊：强调 AI 带来的项目完成速度；
- 基础训练区：强调独立理解和基本功；
- 条件桥：表达学习阶段、使用方式和目标等成立条件；
- 长期效果迷雾区：表达当前材料不足以确认的长期影响；
- 引导任务：用户至少发现一处此前没有意识到的条件或分歧，并能回到对应原文。

## 10. MVP 边界

首个可演示版本建议只承诺：

- 保留现有 3D 观点宇宙和火箭过渡；
- 完整制作一个分岔之城；
- 制作一个缩小版失落档案馆；
- 其余星球只展示外观、名称和降落预告；
- 不同世界复用移动、对话、来源查看和观点比较系统；
- 不把入口预览写成已经可以完整探索的世界。

核心验收标准不是地图数量，而是用户完成一次探索后，能否准确说出一处此前没有意识到的分歧或成立条件，并定位到支撑它的原始材料。
