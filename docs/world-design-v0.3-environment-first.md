# OpinionSpace 世界设计 v0.3：环境优先探索

> 状态：路线验证版。目标不是一次定稿最终美术，而是验证“无人环境探索 + 看山解释”是否比“NPC 即观点”更适合 OpinionSpace。

## 1. 核心命题

旧版默认：**观点 = NPC，用户通过和人对话理解观点。**

v0.3 改为：

> **观点塑造世界，证据留在世界里，看山帮助用户读懂世界。**

用户不是来到一张地图上依次找人聊天，而是进入一个由知乎讨论材料塑造出来的微缩世界。场景先制造问题，看山再解释：眼前的物件、道路、迷雾或遗迹，分别对应哪些真实观点、来源、条件与未知。

## 2. 主交互循环

1. **看见**：用户发现异常环境或有意义的物件。
2. **靠近 / 调查**：物件产生高亮，用户主动交互。
3. **看山介入**：先解释“为什么这里会有这个东西”。
4. **核验来源**：展示对应知乎原回答，不让环境隐喻冒充事实。
5. **收下观点**：观点进入背包，供后续比较、态度标记与碰撞。
6. **继续探索**：用户逐渐理解整个问题的分歧结构。

## 3. 场景信息映射

| 讨论结构 | 场景表达 |
| --- | --- |
| 一类观点 | 一块区域 / 一种空间状态 |
| 单个关键观点 | 可调查物件或局部场景 |
| 原文证据 | 档案、记录、票据、屏幕等可核验材料 |
| 条件性结论 | 闸机、门票、时刻表、条件桥 |
| 证据不足 | 迷雾、未完成结构、黑暗区域 |
| 高频 / 高赞 | 更显眼的建筑或信号，而非“更正确” |
| 少数处境 | 偏远、安静或缺席的空间 |
| 观点共同前提 | 共享设施、汇合道路、地下连接 |
| AI 推演 | 半透明规则装置 / 未完成结构，明确区别于真人来源 |

## 4. 首个验证世界：裸辞

当前 `q_luoci` 从 NPC 路线替换为 8 个环境观点载体：

- 离职申请箱：身心状态恶化时及时止损；
- 现金流账本台：先计算生活费缓冲与议价风险；
- 在职试验工坊：先投递、面试、做作品集，用真实反馈校准；
- 转行售票机：需要整块时间做深度转型，但有明确使用条件；
- 仲裁档案柜：离职之外还存在取证、协商和仲裁路径；
- 无人休息长椅：区分主动选择与单纯逃离；
- 机会时刻表：某些行业 / offer 状态可能形成窄窗口；
- 条件闸机：AI 融合出的“退出阈值”候选规则，明确标为推演。

## 5. 看山的角色

看山不再是地图上的普通 NPC，也不替某一派观点代言。

它承担三件事：

1. **解释环境**：把场景隐喻还原为当前材料中的讨论结构；
2. **标注边界**：明确区分“原回答事实 / 系统解释 / 尚未知”；
3. **提供下一步**：看原文、收观点卡、比较观点、继续探索。

## 6. 视觉方向

MVP 采用 **小型 2D/2.5D Diorama（微缩景观）**，而不是大型 RPG 地图：

- 弱化格子、区域边框和阵营标签；
- 一个世界控制在少量精致区域与 6–10 个关键交互物；
- 允许 WASD / 点击移动，但视觉上不暴露网格；
- 环境物件先用 CSS 原型验证，方向成立后再统一替换成同风格 2.5D 素材；
- 场景整体优先“可读、克制、可探索”，不追求堆满装饰。

## 7. 技术迁移原则

为了不浪费已完成工程，v0.3 第一阶段**不立即删除 `NpcConfig` 数据管线**：

- 固定观点继续通过现有 `NpcConfig → Opinion → Source → Dialogue` 链路供数据；
- `WorldScene` 在 `diorama-v1` 下把这些节点渲染为环境物件而不是人物；
- 来源追溯、观点卡、态度、比较、场景反馈继续复用；
- 路线确认后，再把兼容层正式抽象成 `WorldArtifact / SceneObject` 数据模型。

这样可以先验证产品方向，再决定是否进行第二阶段数据模型重构。

## 8. 下一阶段

若环境优先路线验证成立，下一步应依次完成：

1. 建立正式 `SceneObject` 数据模型，解除对 `NpcConfig` 的兼容依赖；
2. 为 Crossroads 制作统一 2.5D Scene Kit；
3. 把“观点结构 → 地图拓扑 → SceneObject”做成 AI 可控生成流程；
4. 让看山根据用户探索历史选择何时介入，而不是每个物件都固定播一段说明；
5. 再扩展 Archive / Machine 等世界语法。
